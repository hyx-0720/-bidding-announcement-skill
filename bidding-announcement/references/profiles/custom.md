# Profile：完全自定义（regime id: `custom`）

## 元信息
- 适用法律：由用户决定（可不引用任何法律）
- 合规：默认**关闭**；用户要求时可 `scripts/check_compliance.py --regime none`（仅逻辑一致性 + 歧视性提示）
- 术语 / 采购方式 / 章节 / 条款 / 样式 / 文风：全部由用户决定

## 入口：是否基于已有公告提取模板（自定义场景第一问）

进入自定义场景后，**先**询问：
> 您可以**上传一份已有的招标公告**（企业或政府的，支持 .docx / .md / .txt），我会提取它的**格式与结构模板**，再结合您新项目的信息生成新公告；也可以**从空白开始**自由自定义。
> 请选择：A. 上传已有公告提取模板　B. 从空白自定义

### 路径 A：基于已有公告提取模板

#### A1：获取文件内容
用户提供文件路径（或放入工作目录）。按格式处理：
- **.docx**：`pandoc "<文件>.docx" -t markdown -o extracted.md` 提取文本与结构（标题/列表/表格）。
- **.md / .txt**：直接读取。
- **.doc（旧版）**：提示用户先另存为 .docx（转换需 LibreOffice，当前环境未装）。
- **.pdf**：用 `pdf` skill 提取文本（如 `python -c "from pypdf import PdfReader; print('\n'.join(p.extract_text() for p in PdfReader('文件.pdf').pages))"`，或 `pdfplumber`/`pdftotext -layout`）。注意：PDF 仅能提取**文本与结构**，**样式（字体/字号/页边距）通常无法可靠还原**，A2 样式提取跳过，导出时用默认样式或由用户指定。扫描件需 OCR（见 pdf skill）。

#### A2：提取样式（仅 .docx，尽力而为）
```powershell
$env:PYTHONUTF8 = "1"
python ".opencode\skills\bidding-announcement\scripts\extract_style.py" "<文件>.docx" --out style.json
```
得到 `{"settings": {...}}`（字体/字号/页边距/标题颜色对齐），导出 DOCX 时并入渲染输入以**保持原格式**。

#### A3：LLM 分析，产出"模板规格"
基于 extracted.md（及 style.json），分析并向用户**回显**：
1. **章节顺序与标题**（如"一、项目概况 / 二、招标范围 / …"）。
2. **术语**（招标人/采购人、投标人/供应商等，沿用原公告用语）。
3. **可复用的固定条款**（原文保留，如保密、免责、报名方式等模板化表述）。
4. **需替换的项目专属字段清单**（项目名称、预算、时间、联系方式等——这些将向用户重新收集）。
5. **提取到的样式**（来自 style.json）。
请用户确认或微调该模板规格。

#### A4：收集新项目信息
仅针对 A3 中"需替换的项目专属字段"提问（沿用 `intake-guide.md` 的一次性/分步两种模式）。固定条款与结构沿用提取结果，不重复询问。

#### A5：生成与导出
按提取的结构+固定条款，填入新信息生成 Markdown；导出 DOCX 时把 style.json 的 `settings` 并入渲染输入 JSON 顶层，保持原格式。

### 路径 B：从空白自定义 → 走下方组装子流程

## 组装子流程（阶段一以"逐步引导 + 一次确认"方式进行）

> 本场景默认即分步引导。**快速路径**：若用户已明确说明完整需求（章节、术语、条款、样式），可跳过逐步提问，直接按其描述组装并在第 6 步统一回显确认。

### 第 1 步：术语与基调
询问并记录：
- 主体称谓：招标人 / 采购人 / 甲方 / 其他
- 投标方称谓：投标人 / 供应商 / 响应人 / 其他
- 公告名称：招标公告 / 采购公告 / 邀请函 / 其他
- 文风：正式公文 / 简洁商务

### 第 2 步：选择并排序章节
从 `../sections-library.md` 的章节积木库中勾选所需章节并确定顺序。也可新增"自定义空白章节"（用户给标题+内容）。

### 第 3 步：逐章填写字段
对每个选中章节，列出该章节的可用字段（来自 sections-library），用户填写或留空（留空即省略）；允许用户自由增删字段。

### 第 4 步：条款选择
- 从 `../clauses/`（gov-procurement / construction / common）中**任选**条款嵌入；
- 或由用户**粘贴自有条款文本**；
- 或本公告不含任何法定条款。

### 第 5 步：样式（传给 render_docx.js 的 settings）
询问（均可用默认）：
- 字体（默认 微软雅黑）
- 正文字号（pt，默认 10.5）
- 主标题颜色（十六进制，默认 383940）
- 页边距（cm）/ 标题对齐（居中/左对齐）

导出时把这些放入 DOCX 输入 JSON 的顶层 `settings`（见 SKILL.md 导出阶段与 `scripts/render_docx.js`）。

### 第 6 步：确认并生成
回显完整的「章节顺序 + 字段 + 条款 + 术语 + 样式」清单，请用户确认后生成 Markdown，再按需导出 DOCX。

## 生成规则
- 严格按用户确认的章节顺序与术语生成；留空字段省略。
- 不主动添加用户未选择的条款。
- 文末按需附 `../clauses/common.md` 免责声明（询问用户是否需要）。
